# kids-points 設計書

作成日: 2026-10-13

## 1. 目的と背景

- 子ども2人（9歳・5歳）に、日常で何かできたときにポイントを付与している。1pt = 10円。
- その管理を、子どもにもわかりやすいWebアプリにする。スタンプ形式で続ける動機をつくり、「ちょきんばこ」の複利で待つと増える体験をさせる。
- 完成したものを会社のLTで発表する。テーマの中心は「子どもの変化」で、作り方は添える程度。ただし効果検証の期間は取れないため、子どもの反応は初期の様子に触れる程度にする。LTの山場はデモ。
- LTの日程は未定で、できるだけ早く発表したい。そのため、早く家庭で使い始めることを優先する。

### 成功の基準

- 家族共用の iPad で、親がスタンプを付与し、子どもが自分の残高とスタンプカードを見て楽しめる。
- ちょきんばこの月末利息が、ルールどおり正しく計算される。
- LT会場で、URLを開くだけでデモ（スタンプ付与 → 1ヶ月すすめる → 利息の演出）を見せられる。

### 前提

- 利用端末は家族共用の iPad 1台。Safari で開き、ホーム画面に追加して使う。
- 家族だけで使う。アカウント登録、サーバー、端末間の同期はなし。

## 2. 用語

| 用語 | 意味 |
|---|---|
| おさいふ | すぐ使えるポイントの置き場所。利息なし |
| ちょきんばこ | 月末に利息がつくポイントの置き場所 |
| スタンプ（ポイント付与） | 親が付与する操作。ポイントはおさいふに入り、スタンプカードに1つ押される |
| 預け入れ | おさいふ → ちょきんばこ への移動。合計ptは変わらない |
| 引き出し | ちょきんばこ → おさいふ への移動 |
| つかう | おさいふからポイントを減らす（お菓子やおもちゃと交換したとき） |
| 開始残高 | アプリ導入時点で既に貯まっているポイント |

## 3. 画面と操作

### 3.1 全体の構成

```
[トップ] 2人のアバターが大きく並ぶ ──タップ──▶ [子どもホーム]
   │
   └ 右上の 🔒 ──PIN──▶ [親メニュー]
```

- iPad の横向きを基本にする。押せる場所はすべて大きめにする（5歳の指でも押しやすいように）。
- 効果音あり（設定でオフにできる）。

### 3.2 トップ画面

- 2人のアバターと好きな色で、大きなボタンを2つ並べる。名前の文字が読めなくても、顔と色で選べるようにする。
- 右上の小さな鍵アイコンから、PINを入力して親メニューに入る。

### 3.3 子どもホーム

- **スタンプカード**: 1枚20マス。押されたスタンプには行動のアイコンが入る。20マス埋まると「カードコンプリート！」の演出が出て、次のカードに進む。過去のカードもめくって見返せる。コンプリート時のポイントボーナスはない。
- **おさいふ / ちょきんばこ**: 2つの入れ物を並べて表示する。
- **ちょきんするボタン**: 子どもが自分で、おさいふからちょきんばこへ預け入れる。PINは不要。
- **利息の演出**: 月が変わって初めて開いたとき、利息がついていれば「ふえたよ！」の演出を出す。その月に引き出していて利息がなかった場合は「こんげつは おやすみ」と表示する。

#### 表示モード（子どもごとに設定）

| | おさない（5歳向け） | おおきい（9歳向け） |
|---|---|---|
| 文字 | ひらがな最小限。アイコンと色が中心 | ひらがなと簡単な漢字 |
| 残高 | コインの数とイラストで見せる | 「120pt（1,200円）」と数字で見せる |
| ちょきんばこ | 演出で増えたことを見せる | 来月の利息見込みと計算式（120pt × 5% = 6pt）も見せる |
| 預け入れ | 「1こ / 5こ / ぜんぶ」の大きなボタン | 上記のボタンに加えて、数字の入力もできる |

### 3.4 親メニュー（PINで入る）

- **スタンプをおす**: 子どもを選ぶ → 定番メニューをタップ、または「とくべつスタンプ」で pt数とメモを入力する。押したあと、子どもの画面にスタンプが押される演出を出す。
- **つかう**: 子どもを選ぶ → pt数と使い道のメモを入力 → おさいふから減らす。
- **ひきだす**: 子どもを選ぶ → pt数を入力 → ちょきんばこからおさいふへ戻す。
- **とりけし**: 直前の操作を1つ取り消す（制限は 4.5 を参照）。
- **せってい**:
  - 子ども: 名前、アバター、色、表示モード
  - 定番メニュー: 名前、アイコン、pt数、対象の子どもの追加・編集・削除
  - 利率（初期値 月5%）
  - PINの変更
  - 開始残高の入力（子どもごと）
  - 効果音のオン/オフ
  - バックアップの書き出し・読み込み
- **デモモード**: 本番データとは別のデモ用データに切り替える。「1ヶ月すすめる」ボタンがある（4.6 を参照）。

## 4. データとルール

### 4.1 基本の考え方

残高は保存せず、すべての操作を取引記録として時系列に積み上げ、残高は記録の合計から毎回計算する。これにより、取り消し・履歴の集計・バックアップを単純にする。記録は削除しない。

### 4.2 保存するデータ

| データ | 項目 |
|---|---|
| 子ども | id、名前、アバター、色、表示モード（`young` / `older`）、並び順 |
| 定番メニュー | id、名前、アイコン、pt数、対象の子どもid一覧、並び順 |
| 設定 | PINのハッシュ、利率、効果音のオン/オフ |
| 取引記録 | id、子どもid、種類、pt数（正の整数）、日時、メモ、定番メニューid、利息の対象月（`YYYY-MM`）、取り消し日時 |
| 演出の既読 | 子どもごとに、利息の演出を最後に見せた対象月 |

### 4.3 取引記録の種類と残高への影響

| 種類 | おさいふ | ちょきんばこ | スタンプ |
|---|---|---|---|
| `opening` 開始残高 | ＋ | | |
| `stamp` スタンプ（定番・とくべつ） | ＋ | | 1つ押す |
| `spend` つかう | − | | |
| `deposit` 預け入れ | − | ＋ | |
| `withdraw` 引き出し | ＋ | − | |
| `interest` 利息 | | ＋ | |

- 残高 = 取り消されていない記録の合計。
- 開始残高はおさいふに入れる。ちょきんばこに入れたい分は、子ども自身が預け入れる。
- スタンプは pt数に関係なく、1回の付与で1つ押す。スタンプカードの何枚目・何マス目かは、スタンプの記録数から計算する。
- 残高を超える `spend` / `deposit` / `withdraw` は受け付けない。残高はマイナスにならない。
- pt数は1以上の整数のみ。

### 4.4 利息の計算

- 対象: ある月の最終時点のちょきんばこ残高。
- 条件: その月に、取り消されていない `withdraw` が1件もないこと。
- 金額: 残高が1pt以上なら `max(1, floor(残高 × 利率))`。残高0なら利息なし。
- 記録: 翌月1日 0:00 の日時で `interest` を記録し、対象月（`YYYY-MM`）を持たせる。同じ子ども・同じ対象月の `interest` は1件までとし、二重計算を防ぐ。
- 条件を満たさず利息がなかった月も、演出の判定のために「この月は利息なし」が判断できるようにする（記録は作らず、計算時に判定する）。
- さかのぼり計算: アプリ起動時と画面復帰時に、未計算の月を古い順にすべて計算する。前の月の利息を含めた残高で次の月を計算する（複利）。
- 計算の開始月: その子どもの最初の取引記録がある月から。
- 日時の基準: iPad の時計（日本時間）。

### 4.5 取り消し

- 対象は、全体で直前の1件のみ（取り消されていない最新の記録）。
- `interest` は取り消せない。
- 利息の計算が済んだ月に属する記録は取り消せない。
- 取り消しは記録を消さず、取り消し日時を記録する。
- 取り消すと残高がマイナスになる場合（例: 預け入れを取り消すとおさいふの残高が足りない）は取り消せない。

### 4.6 デモモード

- 本番とは別のIndexedDBデータベースを使い、本番データに一切影響しない。
- 初回、またはリセット時に、デモ用の子ども2人（9歳想定・5歳想定）と、過去3ヶ月分の取引記録を作る。
- アプリ内の現在時刻を「実際の時刻 + 進めた月数」とする。「1ヶ月すすめる」を押すと進めた月数を1増やし、利息を計算して演出を出す。
- 「デモをリセット」で初期状態に戻せる。
- デモ中は画面に「デモ」と常に表示する。

### 4.7 PIN

- 4桁の数字。初回起動時に設定する。
- 子どもが勝手に親の操作をしないための鍵であり、強固なセキュリティは目的としない。保存はハッシュ化する。
- 忘れたときのリセット: トップ画面の鍵アイコンを長押しすると確認画面が出る。足し算の問題（2桁 + 2桁）に答えるとPINを再設定できる。データは消えない。

### 4.8 バックアップ

- 全データ（子ども、定番メニュー、設定、取引記録）をJSONファイルとして書き出す。
- 読み込み時は、内容を確認する画面を出したうえで、現在のデータを丸ごと置き換える。
- 最後の書き出しから30日以上たつと、親メニューで書き出しを促す表示を出す。

## 5. 技術構成

| 用途 | 使うもの |
|---|---|
| 土台 | Vite + React + TypeScript |
| データ保存 | IndexedDB（Dexie） |
| オフライン対応・ホーム画面に追加 | vite-plugin-pwa |
| 演出 | CSSアニメーション |
| テスト | Vitest、React Testing Library |
| 公開 | GitHub Pages |

### フォルダ構成

```
kids-points/
  src/
    domain/   … 残高・利息・取り消し・スタンプカードのルール。画面やDBに依存しない純粋な関数
    storage/  … IndexedDBへの読み書き、バックアップ、デモ用データの生成
    ui/       … 画面とコンポーネント（child / parent / common）
  docs/       … 仕様書・実装計画
```

- `domain/` の関数は「記録の一覧と現在時刻」を受け取り、結果を返す。現在時刻を引数で受け取ることで、デモモードとテストで同じロジックを使う。

### iPad での注意点

- Safari は、ホーム画面に追加していないサイトのデータを、しばらく使わないと削除することがある。ホーム画面への追加を前提とし、初回起動時に追加方法を案内する。
- 定期的なバックアップ書き出しで、端末の故障や紛失に備える（4.8）。

### 公開とデータの扱い

- GitHub Pages で静的ファイルとして公開する。URLは公開されるが、サーバーにデータはなく、データは各端末のIndexedDBにのみ存在する。
- LT会場では、同じURLをデモモードで開いてデモを行う。

## 6. テスト

- `domain/` はテストを先に書いて実装する。最低限、次のケースを含める。
  - 各取引種類による残高の増減
  - 残高不足の `spend` / `deposit` / `withdraw` の拒否
  - 月末利息の計算（切り捨て、最低1pt保証、残高0なら利息なし）
  - 引き出しをした月は利息なし。引き出しを取り消した場合は利息あり
  - 複数月のさかのぼり計算と複利
  - 同じ月の利息の二重計算の防止
  - 取り消しの制限（利息、計算済みの月、残高がマイナスになる場合）
  - スタンプカードの枚数とマス目の計算
- 画面は、スタンプ付与・預け入れ・つかうの主要な流れを軽くテストする。
- 最後に実機の iPad（ホーム画面に追加した状態）で確認する。

## 7. やらないこと

- 端末間の同期、アカウント、サーバー
- カードコンプリート時のポイントボーナス
- 子どもの写真の取り込み（アバターは用意したイラストから選ぶ）
- LT用のグラフ機能（必要になったら、取引記録の書き出しから別途作る）

## 8. 進め方の優先順位

1. 家庭で使い始められる最小構成: 子ども・PIN・スタンプ（定番/とくべつ）・おさいふ/ちょきんばこ・預け入れ・引き出し・つかう・月末利息・開始残高・取り消し・バックアップ
2. 演出（スタンプ、利息、カードコンプリート）と表示モードの作り分け
3. デモモード
